# Payload-Vs-Code Discrimination Frontiers via Per-Session Egress Budgets for Plugin Sprawl Widening The Egress Surface

## The Idea
This proposal targets closing agent-driven exfiltration paths without breaking workflows in the **ai_egress** domain. It combines a
per-session egress budgets — where each agent session gets a hard outbound volume and call-count budget — with a deliberately adversarial
reading of the plugin sprawl widening the egress surface problem: every new tool adds an unreviewed outbound path. The novel step is the
twist: embedding thresholds trained to separate natural-language payloads from code.

In operation, the system treats false-positive rate as the first-class observable. Every
design decision is evaluated against it under the model of an injected instruction trying to move secrets across the egress boundary. Unlike a
straight deployment of per-session egress budgets, the twist changes what an observer can learn
from the outside: the mechanism's cost curve is reshaped so that the promised improvement
holds where it matters — must log every blocked attempt for audit.

Why now: the channel window shows sustained interest in agent_egress_policy, semantic_egress_filter-adjacent
techniques, while the open problem remains plugin sprawl widening the egress surface. The combination is new in
this framing, and its falsifiable form makes it testable with a prototype plus simulation
before any large-scale commitment.

## Hypothesis
We hypothesize that embedding thresholds trained to separate natural-language payloads from code — implemented through each agent session gets a hard outbound volume and call-count budget — can halve the false-positive rate at equal detection recall when addressing every new tool adds an unreviewed outbound path, under the constraint of must log every blocked attempt for audit, measured by false-positive rate.

## Proposed Testing Method
Build a minimal prototype of per-session egress budgets with payload-vs-code discrimination frontiers and evaluate against a baseline without the twist. Simulation first: model an injected instruction trying to move secrets across the egress boundary and replay traces sampled from the domain's channel window plus synthetic workloads. Vary one factor at a time; report exfiltration success rate, false-positive rate, detection dwell time with confidence intervals over at least thirty seeds. Acceptance: the hypothesis improvement must hold at p<0.05 with the twist alone, and regressions on the other metrics must stay within ten percent of baseline. Follow with a small live-network pilot if simulation gates pass.
